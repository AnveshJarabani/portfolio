Replacing Legacy BI: A Migration Playbook

How a healthcare SaaS company replaced $450K/yr in BI licensing with an open-source stack at $21K/yr — while adding AI-powered analytics.

Anvesh Jarabani · July 2026 · 12 min read
The Problem

The legacy BI stack was built on SSIS ETL packages feeding a SQL Server data warehouse, visualized through a commercial BI tool with 900+ seats at ~$450K/yr. Reports lived outside the clinical workflow — users had to leave the application, log in separately, and navigate a disconnected interface. Meanwhile, the application monolith served 130+ embedded reports via direct database queries, with no caching or semantic layer.

Key finding from monolith scan: 95% of the application's reports are read-only. Only 5% need write-back capability. This means the vast majority of reports can be served from a cached semantic layer with zero load on the primary database.
GCP Service Selection

Six GCP services form the infrastructure backbone. Each was chosen for a specific reason — no service exists "just because."

BigQuery
Data warehouse with 5-layer ELT. Scanned only on pre-aggregation refresh, not per dashboard load. Eliminates per-query cost at the visualization layer.
Datastream
CDC replication from the primary database. VPC peering. 15-minute freshness with continuous merges. Continuous change capture without batch ETL.
Cloud Storage (GCS)
Pre-aggregation staging bucket. CSV.GZ with 1-day auto-delete lifecycle. Zero storage costs — ephemeral staging between BigQuery and CubeStore.
Vertex AI
Gemini 2.5 Flash for NL-to-SQL analytics. Vendor-agnostic via LiteLLM proxy. Powers the conversational AI layer.
Artifact Registry
Container images for Superset, Cube.js, and the chat service. Version-controlled Docker builds. Private container registry for all platform services.
Terraform
Google provider v6.50. Manages GCS, Artifact Registry, Datastream, BigQuery — fully declarative, reproducible, auditable infrastructure as code.
Dataform 5-Layer ELT

322+ SQL models replacing 309 GUI-based SSIS packages. Pure SQL, version-controlled in Git, with 153+ built-in assertions for data quality.

Dataform refresh tiers: Hot (~30 models, 15-min refresh), Warm (~100 models, 3-hour refresh), Cold (remaining, daily). Cloud Scheduler replaces SQL Agent jobs entirely.
Conversational Analytics

Ask questions in plain English — get data-driven answers. The LLM never touches the warehouse directly. All queries route through the semantic layer's pre-aggregation cache, so there's zero risk of expensive full-table scans.

Example questions:

  • "What's our conversion rate by branch this month?"
  • "Show payer mix by region for the last quarter"
  • "Compare census trends across clinics last 6 months"
  • "Which branches have the highest average length of stay?"
Safety constraint: The LLM generates SQL against Cube.js's schema — never raw BigQuery tables. Every query is scoped by organization_path via queryRewrite(), ensuring multi-tenant isolation even in ad-hoc AI queries.

Application-Embedded Analytics

Dashboards and AI chat live inside the application — zero context-switching. No separate login, no separate tab.

1
User
Logs into the application via Okta OIDC. JWT contains organization_path and roles.
2
Application
Renders <iframe> on the Reports page. Guest Token API receives the forwarded JWT — seamless embed with no additional login.
3
Semantic Layer
queryRewrite() injects organization_path filter on every query. User sees only their organization's data.
4
AI Chat
Same JWT feeds the same RLS rules. Users ask natural-language questions in the same context — no tool switching.
